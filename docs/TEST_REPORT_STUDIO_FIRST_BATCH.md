## 实际编码验收

新增集成用例从浏览器导入含真实测试图片的 ProjectIR，通过界面提交实际渲染，再通过真实下载链接取得 MP4。6 秒样片检查：

- H.264、1280×720、AAC 和实际时长。
- 上传的橙色产品图确实出现在编码帧中；测试没有替换渲染器、媒体解码或 API。
- 指定时间的粉色字幕像素存在；三个镜头的编码画面有明显变化。
- FFmpeg 音量检查排除静音音轨。

代码另生成 [9 秒演示片](../deliverables/NEXUS-STUDIO-FIRST-BATCH-720p.mp4?raw=true)，包含原创矢量产品、经过参数化适配的 ShotCraft 文字隧道、代码构造的图层、三段字幕、原创配乐与两条音效。实测 9.003 秒、1280×720、30fps、H.264＋AAC，文件 3,160,492 字节；本次并行测试环境下渲染 46.812 秒，不作为腾讯云或所有工程的性能承诺。

SHA256：`0943f06423c1dffc9821c038963df66582f04a3407b7b6907e9c31d467cf3e60`。机器记录见 [验证文件](../deliverables/NEXUS-STUDIO-FIRST-BATCH-VERIFICATION.json)，参数见 [可重开工程](../examples/studio-first-batch-sample.json)。从编码文件抽取三个镜头画面并人工查看，没有把原片、用户产品或私人素材发布到仓库。

## 已发现并修复的问题

1. 直接在受严格校验的字段上输入，会让清空标题和输入半截数字时回退。新增局部输入草稿，完整有效的值才进入工程；恢复版本／撤销使用布局阶段同步显示，加入真实浏览器回归。
2. 加入新入口会影响旧本机包的依赖树和许可证集合。用字面构建标记排除新 Studio 的代码／CSS，历史广告包只包含其实际使用的许可文件；0.5.4 广告包重新构建后与原件字节相同，SHA256 仍为 `5df65ba990730e107d94391e1f65ab5690a1fe63a3215bc69dc22de68f6da81b`。
3. 需要让时间线分割保留真实源时间。右片段增加 `sourceInFrame`，关键帧沿用源帧；Node 用例逐帧比对分割前后的变换，浏览器检查分割后的裁入和时长。
4. 多个客户端保存可能覆盖新数据。服务端串行执行写入并比对 revision，并发测试证明一条成功、一条返回 409；损坏工程拒绝覆盖，原字节保留。

5. 桌面固定工作区改造后，手机预览的百分比高度会被压缩。为窄屏添加明确画幅比例，并加入预览高度与无横向溢出的浏览器检查。
